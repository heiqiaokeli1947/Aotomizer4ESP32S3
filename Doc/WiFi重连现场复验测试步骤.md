## 1. 测试目的

验证设备连续运行中 WiFi 断开后，能够在 **30 秒内自动发起射频复位式重连**，并在路由器/热点恢复后 **30 秒内自动恢复在线**，无需断电重启。

核心修复机制：断线后 `startReconnect()` 执行 `active(False) → 1s → active(True) → connect()` 完整射频电源循环，强制重走扫描→认证→关联→DHCP。

## 2. 测试环境与准备

| 准备项 | 要求 |
|---|---|
| 设备 | ESP32-S3 雾化控制器，已烧录 202610070001 版本全部源码 |
| 供电 | USB 接电脑（便于看串口日志）或现场电源 |
| AP | **手机热点**（推荐，可随时开关）或现场路由器；2.4GHz 频段 |
| 热点参数 | 名称 `cissco_2g`，密码 `13438045703`（与设备已存配置一致；如不同则先通过配网页面设置） |
| 串口工具 | 电脑装 Thonny，或已装 mpremote（`python -m pip install mpremote`） |
| 串口连接 | USB 线连接板子，端口 **COM43**（以实际设备管理器为准），波特率 115200（USB-CDC 自动适配） |

**开始串口监视（二选一）：**

- Thonny：打开 → 右下角解释器选 MicroPython (ESP32) → 端口 COM43 → Shell 区可见日志
  - 注意：Thonny 与 mpremote 不能同时打开串口
- 命令行：
  ```
  python -m mpremote connect COM43 repl
  ```

> **复位方式：** 直接拔插 USB 重新上电（硬复位）。不建议用 mpremote soft-reset——WDT 跨软复位继续生效会触发一次硬复位（属正常保护，但日志多一段 crash 输出）。

## 3. 关键判定信号（日志为权威）

| 信号 | 含义 |
|---|---|
| `connect wifi success. broadcast node ip.` | 开机/重连后 WiFi 成功，进入 normal 模式 |
| `get IP success:x.x.x.x` | 广播线程（每 60s）确认在线 |
| `wifi reconnect (radio restart):cissco_2g` | **本次修复核心日志**：主循环检测到断线并发起复位式重连 |
| `get IP failed.` | 广播线程确认离线 |
| RGB LED **绿色** | 在线（`(0,255,0)`） |
| RGB LED **品红（紫）** | 离线（`(255,0,255)`） |

> ⚠ **LED 有延迟**：LED 由广播线程每 **60 秒**刷新一次，状态变化后最多 60s 才变色。**判定重连时序以串口日志为准**，LED 仅作辅助。

## 6. 通过判据

- **必过**：TC1、TC2、TC3、TC6 全部通过；TC4 三次循环零人工干预
- **建议通过**：TC5 连续 ≥48h 在线或期间掉线全部自动恢复
- 任一核心用例失败：保留完整串口日志（从上次上电到失败时刻），记录失败时的路由器/热点状态

## 7. 常见问题

| 现象 | 说明/处理 |
|---|---|
| 串口打不开 / `it may be in use` | Thonny 占用了 COM43：Thonny 中断开后端或关闭，再连 |
| LED 变色慢 | 正常，LED 60s 刷新一次；以日志为准 |
| 关热点后超过 35s 才见重连日志 | 检查主循环是否在 normal 模式（配网模式不发起重连，日志显示 `config mode left ...`） |
| 重连日志有但一直连不上 | 确认热点名称/密码未变、是 2.4GHz、信号正常；热点恢复后应在下个 30s 周期连上 |
| 出现一次 WDT crash 后自动重启 | 若刚做过软复位属正常；正常运行中出现则需保留日志报故障 |
